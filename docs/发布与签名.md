# 发布与代码签名（Windows）

本文档说明把选课助手发布到 Windows 平台的完整流程：构建 → 检查 → 签名 → 分发。
面向要在 Windows 上出正式包的人（构建脚本本身可在 Linux 上交叉编译出 exe，但托盘壳必须 Windows 构建）。

## 1. 发布前检查清单

| 项 | 说明 |
|---|---|
| 版本号 | 用 `npm run pack:src -- --version vX.Y.Z` 会**同步更新本地 package.json**，保证之后 `pack:win` 读到的版本一致 |
| 托盘壳 | `CourseHelperTray.exe` 必须在 **Windows 上**用 `npm run build:tray` 构建（见下） |
| 图标 | `CourseHelper.exe` 的图标/版本信息由 `scripts/winres.mjs` 在打包时自动写入（来源 `CourseHelper.png`） |
| 本机监听 | 后端只监听 `127.0.0.1`（`server/index.ts`），不再触发 Windows 防火墙弹窗；如需跨机访问可设 `HOST=0.0.0.0` |
| 数据目录 | Windows 下存档保存在 `%APPDATA%\CourseHelper`（不是 exe 旁边），删程序/换目录不丢数据 |
| 实机验证 | 在干净 Windows 上走一遍：启动 → 打开网页 → 插件导入 → 双开托盘 → 退出 |

## 2. Windows 完整构建

在 **Windows**（已装 Node.js ≥ 18 与 Rust MSVC 工具链）上：

```powershell
# 1) 安装依赖
npm install

# 2) 构建托盘壳（需 Rust；产出 tray/course-helper-tray.exe）
npm run build:tray

# 3) 一键打包（构建前端 + 插件 + 后端 exe + 写入图标/版本 + 组装 + 压缩）
npm run pack:win -- --version v0.5.0alpha
```

产物：

```
releases/windows-amd64-v0.5.0alpha/
  CourseHelper.exe        后端（pkg 打包，含图标/版本信息，GUI 子系统不弹控制台）
  CourseHelperTray.exe    托盘壳（双击这个）
  dist/                   网页
  extension/              浏览器插件（未打包）
  README.txt              使用说明
releases/windows-amd64-v0.5.0alpha.zip
```

> 若在 Linux 上跑 `pack:win`：能交叉编译出 `CourseHelper.exe`（首次会联网下载 pkg 基础二进制），但**不会**包含托盘壳（脚本会打印警告）。完整客户端请在 Windows 上构建。

## 3. 代码签名

未签名的 exe 下载后会被 SmartScreen 拦截为「未知发布者」，且易被杀软误报。正式对外发布建议签名。

### 3.1 证书类型怎么选

| 类型 | 成本 | SmartScreen 表现 | 适合 |
|---|---|---|---|
| **自签名**（`New-SelfSignedCertificate`） | 免费 | 仅本机信任；别人下载仍警告 | 内部测试、给信任的人 |
| **OV 代码签名证书** | 约 ¥1000+/年 | 显示发布者名称，但 SmartScreen 声誉需**积累**（初期仍可能提示） | 有公司资质、预算有限 |
| **EV 代码签名证书** | 约 ¥2000+/年，需 USB 硬件令牌 | **立即**通过 SmartScreen，无未知发布者警告 | 面向大众分发，推荐 |

- 渠道：Sectigo、DigiCert、GlobalSign、Certum（便宜）、SSL.com 等；国内可找其代理商。
- 个人无公司：Certum / Sectigo 提供「个人代码签名证书」，但 SmartScreen 信任度低于企业 EV。
- 流程：官网提交身份/企业资料 → 审核（OV/EV 会电话/邮件核实）→ 下载 `.pfx`（OV）或收到 USB token（EV）。

### 3.2 用 Windows SDK 的 signtool 签名

先安装 [Windows SDK](https://developer.microsoft.com/windows/downloads/windows-sdk/)（含 signtool），然后：

```powershell
# OV：用 .pfx 文件
signtool sign /fd SHA256 /a `
  /f "C:\certs\mycode.pfx" /p <密码> `
  /tr http://timestamp.digicert.com /td SHA256 `
  "releases\windows-amd64-v0.5.0alpha\CourseHelper.exe"

# 托盘壳也要签
signtool sign /fd SHA256 /a `
  /f "C:\certs\mycode.pfx" /p <密码> `
  /tr http://timestamp.digicert.com /td SHA256 `
  "releases\windows-amd64-v0.5.0alpha\CourseHelperTray.exe"
```

验证：

```powershell
signtool verify /pa /v "releases\windows-amd64-v0.5.0alpha\CourseHelper.exe"
```

### 3.3 关键顺序（重要）

1. `npm run pack:win`（内部会先 pkg 打包 → 改 GUI 子系统 → **写入图标/版本** → 组装 → 压缩）。
2. **签名必须在写入图标/版本之后**（否则改字节会使签名失效）。要么对 `releases/.../` 里的 exe 手动签，要么把上面的 signtool 命令接到 pack.mjs 的压缩步骤前。
3. 两个 exe 都签完，再对外分发 zip。

### 3.4 SmartScreen 与杀软误报

- **EV 证书**可即时通过 SmartScreen；**OV** 需要下载量/声誉积累，初期用户仍可能看到「Windows 已保护你的电脑」→ 点「仍要运行」。
- 若 Defender/第三方误报，去 <https://www.microsoft.com/en-us/wdsi/filesubmission> 提交申诉（选「Incorrectly detected」），附上 exe。
- 本项目 exe 用 pkg 打包，属于「打包/加壳」形态，个别杀软启发式可能误报；签名能显著降低误报率，但不能 100% 消除。

## 4. 数据目录说明

- **Windows（pkg exe）**：`%APPDATA%\CourseHelper\`（`settings.json`、`saves\`、`backup\`）。
- **Linux（pkg 二进制）/ 开发环境**：exe（或项目根）旁的 `data\`。

托盘壳从 `%APPDATA%\CourseHelper\settings.json` 读上次端口，与后端一致。

## 5. 可选：CI 自动出包

目前手动构建即可。若以后要自动出包，用 GitHub Actions 的 `windows-latest` runner：

```yaml
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
    with: { node-version: 20 }
  - uses: dtolnay/rust-toolchain@stable
  - run: npm ci
  - run: npm run test:ext
  - run: npm run build:tray
  - run: npm run pack:win -- --version ${{ github.ref_name }}
  - uses: actions/upload-artifact@v4
    with:
      name: windows-release
      path: releases/*.zip
```

> 注：签名证书/密码属于机密，建议放 GitHub Secrets，只在发布 tag 时注入。

## 6. 可选：插件分发

`extension/` 目前是未打包插件（开发者模式加载）。面向非技术用户可选：

- 打成 `.crx` 分发给 Chromium 内核浏览器（Chrome 从商店外的 .crx 安装受限制，Edge/某些环境可）。
- 上架 Chrome Web Store（`manifest.json` 已满足 MV3，权限也收敛到教务域名 + localhost）。

上架需开发者账号（一次性 $5）并按商店要求补充隐私说明与截图。
