# 选课助手 · 浏览器插件集成设计稿

> 版本 v0.1（设计稿）｜状态：待确认后实施 ｜适用范围：西北工业大学教务/选课系统

---

## 0. 文档目的

本文档是「通过浏览器插件捕获教务系统网页信息，并与本应用联动」的**详细设计稿**，回答四个问题：

1. 插件与服务器**如何分工**（共存 / 全进插件 / 其他）——见 §3；
2. 插件如何**不碰密码、复用已登录会话**地拿到课程开课/选课数据；
3. 插件如何**静默请求**一次性拉取某门课的全部开课时间与教师信息；
4. 插件如何在教务网页上**加快捷按钮**，把课程一键送入本应用的候选/已选列表。

文末第 12 节列出**待确认项**（教务系统域名/端点、目标浏览器等），标 `[待确认]` 的项需在实施前落实；其余为设计决定（标 `[决定]`）。

---

## 1. 目标与痛点回顾

| 痛点 | 结论 |
|---|---|
| 校内系统不允许多设备登录，这边登录那边掉线 | 插件复用「用户已登录的那个浏览器」的会话，**不建立第二登录态** |
| 内置登录不安全（被篡改后泄露密码） | 插件**永不接触、永不存储账号密码**，只读页面已有的会话 |
| 内置登录麻烦（需时常重新登录） | 登录与否由用户自己在浏览器里掌控，插件随登录态自动有效 |
| 手工复制粘贴易错、列错位 | 插件直接在 DOM/接口层解析，结构稳定 |

**结论**：插件是「会话借用者 + 数据搬运工」，本应用仍是**全屏标签页**里的主操作界面，二者通过 `localhost` 的既有 API 联动。

## 2. 需求拆解

| 需求 | 实现方式 | 对应组件 |
|---|---|---|
| 获取某课程开课情况（所有开课时间 + 教师 + 容量） | 静默请求适配器（优先）/ DOM 抓取（兜底） | content script |
| 获取选课情况（已选人数、容量、本人已选结果） | 同上，字段映射到 `enrolled`/`capacity`/`selected` | content script |
| 网页加快捷按钮并联动（加入候选列表等） | 注入浮层按钮 → 消息 → background → `/api/command` | content script + background |
| 操作页面铺满标签页 | 主应用保持全屏标签页；插件只做抓取 + 深链打开，不内嵌 UI | popup / background |

## 3. 实现方案对比与选型（评估）

### 3.1 三种形态

| 方案 | 形态 | 一句话 |
|---|---|---|
| **A 插件 + 服务器共存（薄插件）** | 插件只做「抓取 + 快捷按钮 + 深链」；服务器/网页继续承担课表、算法、存档、AI | 把「必须待在浏览器里」的那一小块交给插件，其余不动 |
| **B 全部集成进插件（无服务器）** | 整个选课助手重写进扩展页 / `chrome.storage`，不再有 Node | 单件安装，但要重做存储 / AI / 外部通道 |
| **C 其他 / 混合** | 纯静态 + PWA、扩展页内嵌 App 等变体 | 介于两者，各有取舍 |

### 3.2 难度与效果对比

| 维度 | A 插件 + 服务器共存 | B 全部进插件 |
|---|---|---|
| 抓取 / 静默请求（两案都要做） | 低~中 | 低~中 |
| 课表 / 算法 / UI | 复用，0 成本 | 可搬，0~低 |
| 存档 / 备份 / 多存档 | 复用文件存档，0 成本 | 重写为 `chrome.storage`，中~高，且丢「外部工具直接改文件」 |
| AI 对话 + 密钥 | 复用服务端代理（key 留服务器），0 成本 | key 存 `chrome.storage`、扩展直连 DeepSeek，密钥隔离变差 |
| 外部工具/AI 通道（`/api/command`、直接改存档） | 保留 | 失效 |
| 安装体验 | 需跑服务器 + 装插件 | 只装插件 |
| **总体难度** | **低~中** | **高** |
| **总体效果** | **高（能力全保留）** | **中（能力回退）** |

### 3.3 选型结论 `[决定]`

**选 A：插件与服务器共存，插件保持「薄」。**

理由：

1. **「捕获」这一层天然只能待在浏览器里**（要 DOM + 页面已登录会话），插件是刚需，无论哪案都逃不掉；
2. 除此之外的**全部能力（课表、冲突检测、70/30 排序、存档、备份、多存档、AI、外部工具通道）已经存在且好用**，搬进扩展是纯成本、效果还回退；
3. 项目已有「薄 Node 后端」的既定决策（`DESIGN.md §13.6`），本方案与之完全一致，不推翻任何东西；
4. 对「单机、技术型用户」而言，「跑一条 `npm run dev`」的代价远小于「重写半个应用」。

**何时才考虑 B**：将来要分发给「完全不会跑 Node 的普通用户」时，再做一个独立的「免服务端版」（`chrome.storage` + 静态打包），现在不必要。

### 3.4 方案 A 内两个可选细节

- **a. 全屏打开入口**：可用扩展页（`chrome-extension://` 全屏）替代 `http://localhost:3001` 作为打开入口——好处是扩展页可无 CORS 直连 localhost、可读 `chrome.storage`；本质仍是 A（服务器承担存储/算法）。
- **b. 抓取结果落地方式**：`/api/command`（结构化）为默认；保留「导出 JSON / 复制文本 → 手动粘贴」作为无服务器时的兜底。

## 4. 总体架构 `[决定]`

```
┌────────────────────────────── 浏览器 ──────────────────────────────┐
│                                                                     │
│  ┌── 教务系统标签页（https://…/xk 等）────────────────────────┐      │
│  │  content script（isolated world）                           │      │
│  │   ├─ DOM 抓取适配器：表格/卡片 → 规范化文本 → ParsedCourse[] │      │
│  │   ├─ 静默请求适配器：fetch(教务系统内部 API)，复用页面会话     │      │
│  │   └─ 注入浮层按钮：「加入候选」「导入为已选」「查询开课」…      │      │
│  └──────────────────────────┬──────────────────────────────────┘      │
│                             │ chrome.runtime.sendMessage              │
│  ┌──────────────────────────▼──────────────────────────────────┐      │
│  │  background service worker                                    │      │
│  │   ├─ 组装 add_course 命令                                     │      │
│  │   └─ fetch POST http://localhost:3001/api/command（走扩展权限）│      │
│  └──────────────────────────┬──────────────────────────────────┘      │
│                             │ HTTP                                   │
│  ┌──────────────────────────▼──────────────────────────────────┐      │
│  │  popup（可选）：状态 + 「打开选课助手（全屏新标签页）」深链      │      │
│  └─────────────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────────┘
                                │ HTTP
┌───────────────────────────────▼─────────────────────────────────────┐
│  本应用后端  http://localhost:3001（已有，无需大改）                  │
│   ├─ POST /api/command（已有，add_course 去重/合并）                  │
│   └─ GET  /api/schedule（已有，前端 2s 轮询自动刷新）                  │
└─────────────────────────────────────────────────────────────────────┘
```

要点：

- **localhost 流量一律走 background service worker**：content script 的 `fetch` 自 Chrome 73 起按页面源走 CORS，且教务页是 `https://` 时直连 `http://localhost` 属混合内容；background 在 `host_permissions` 声明 `http://localhost:3001/*` 后不受 CORS/混合内容限制，最稳。
- **教务系统接口请求在 content script 内发起**（同源请求，自动携带页面会话 Cookie/token），无需把凭证传给 background。

## 5. 组件划分

### 5.1 `manifest.json`（Manifest V3，Chromium）`[决定]`

```jsonc
{
  "manifest_version": 3,
  "name": "选课助手·教务捕获",
  "version": "0.1.0",
  "permissions": ["storage"],                       // 仅本地配置
  "host_permissions": [
    "http://localhost:3001/*",                      // 本应用 API
    "https://*.nwpu.edu.cn/*"                        // 教务系统（待确认域名）
  ],
  "background": { "service_worker": "background.js" },
  "content_scripts": [
    {
      "matches": ["https://*.nwpu.edu.cn/*"],        // 待确认具体页面
      "js": ["content.js"],
      "run_at": "document_idle"
    }
  ],
  "action": { "default_popup": "popup.html" },
  "options_ui": { "page": "options.html", "open_in_tab": false }
}
```

> 不需要 `cookies`、`webRequest`、`tabs` 等高危权限——插件不读 cookie、不拦截请求，仅借页面会话发请求。这是「不碰密码」在权限层上的体现。

### 5.2 content script（`content.js` / `content.ts`）

职责：

1. **识别页面类型**（课程信息列表页 / 课程详情页 / 选课页 / 我的已选课页），切换适配器。
2. **DOM 抓取**：定位表格/卡片，按已有文档 `docs/西工大课程网页文本格式.md` 的列序重建「规范化文本块」，交给 `parseWebCoursesText`（复用 `shared/webtext.ts`，零重复解析逻辑）。
3. **静默请求**：调用教务系统内部接口（见 §6.2）。
4. **注入浮层按钮**：每个课程行/卡片旁加按钮；对 SPA 页面用 `MutationObserver` 监听异步渲染后重新注入。
5. **回显结果**：在页面内用轻量 toast 显示「已加入候选 ✓ / 已导入为已选课 ✓ / 目标未启动」。

### 5.3 background service worker（`background.js`）

- 监听 `chrome.runtime.onMessage`，处理三类消息：

```ts
type ExtMessage =
  | { type: 'IMPORT_COURSES'; courses: ParsedCourse[]; category: Category } // 结构化导入
  | { type: 'IMPORT_RAW_TEXT'; text: string }                               // 兜底：原始文本走 /api/parse
  | { type: 'PING' }                                                        // 探测本应用是否在线
  | { type: 'OPEN_APP' };                                                   // 打开全屏标签页
```

- `IMPORT_COURSES` → 组装 `add_course` 命令 → `POST http://localhost:3001/api/command`。
- `PING` → `GET /api/schedule`，供 popup 显示「本应用已连接/未启动」。
- `OPEN_APP` → `chrome.tabs.create({ url: baseUrl })` 打开**全屏新标签页**。

### 5.4 popup 与 options

- **popup**：极简状态面板——本应用是否在线、当前存档、一个「打开选课助手（全屏标签页）」按钮。**不承载课表 UI**（见 §9）。
- **options**：配置本应用地址（默认 `http://localhost:3001`，开发期可改 `http://localhost:5173`）、默认导入类别（`elective`/`required`/`builtin`）。

## 6. 两条数据通路

### 6.1 DOM 抓取（开箱即用，兜底）`[决定]`

适配器把 DOM 表格**重建为既有解析器认识的文本格式**，再复用 `parseWebCoursesText`：

```
<table> 各行/各单元格（按固定 7 列序）
   ──→ 规范化文本块（等价于「粘贴出来的文本」）
   ──→ parseWebCoursesText(text)   // 复用 shared/webtext.ts，规则已被验证
   ──→ ParsedCourse[]
```

- 优点：无需逆向接口，页面改版只影响「DOM → 文本」这一段选择器，解析规则不变。
- 缺点：依赖页面 DOM 结构，列被折叠、懒加载时需配合 `MutationObserver` 与「展开全部」触发。
- 精确的表格选择器/列序需对着真实页面调（见 §12 待确认项）。

### 6.2 静默请求（复用会话，一次性拉全开课信息）`[决定·需端点]`

用户明确希望「静默请求，一次性查询本课程所有开课时间与教师信息」。这要求教务系统存在可被页面调用的内部接口。设计上把「端点差异」收敛为一个适配器接口：

```ts
interface SessionCtx {
  baseUrl: string;                       // 教务系统 API 基地址
  headers?: Record<string, string>;      // 页面用到的 XSRF-token / 自定义头
}

interface ProviderAdapter {
  readonly id: string;
  matches(url: string, doc: Document): boolean;             // 该适配器负责此页？
  extract(doc: Document): ParsedCourse[];                   // DOM 抓取（必有）
  queryOfferings?(ctx: SessionCtx, code: string): Promise<ParsedCourse[]>;      // 单课静默查询
  queryOfferingsBatch?(ctx: SessionCtx, codes: string[]): Promise<ParsedCourse[]>; // 批量（可选）
}
```

- 默认 provider 只实现 `extract`（DOM 抓取），**立即可用**；
- `queryOfferings` 系列在拿到真实端点后补上，实现「点一个『查询开课』按钮 → 一次请求拉回该课全部时间段 + 教师 + 容量 + 已选人数」。

**端点已确认**（见附录 A §13.2）：`GET /student/for-std/lesson-search/semester/{semesterId}/search/308509?courseCodeLike=<编号>&assembleFields=…`，返回 DataTables **结构化 JSON**，每行一个教学班（候选），含 `course.code/nameZh/credits`、`stdCount`(已选)、`limitCount`(容量)、`teacherAssignmentList`(教师)、`scheduleText.dateTimePlacePersonText.textZh`(时间地点)。「一次性查某课全部开课时间+教师」= 带 `courseCodeLike` 调一次即可。**静默请求完全可行，且为结构化 JSON，最稳。**

## 7. 与「本应用」的联动

### 7.1 复用 `/api/command`，无需新端点 `[决定]`

`ParsedCourse → add_course` 命令映射：

```jsonc
{
  "op": "add_course",
  "name": "计算机网络原理",
  "code": "U10M11016",
  "category": "elective",               // 见 §7.2
  "credit": 3,
  "options": [
    {
      "label": "U10M11016.01",           // 教学班编号，用作候选去重键
      "enrolled": 12,                    // 已选人数（识别到才带，否则省略字段）
      "capacity": 90,                    // 容量
      "segments": [ /* 全部开课时间段 */ ]
    }
  ]
}
```

关键收益：现有 `applyCommand` 的 `add_course` **已内置我们需要的语义**——

- 按 `code`（无则 `name`）查重 → 重复导入不建新课；
- 按教学班编号 `label` 合并候选 → 同一门课多个教学班自动聚合成多候选；
- **「识别到才覆盖」**：`rating/enrolled/capacity/segments` 用 `!= null` / `length>0` 判断，未识别字段保留旧值 → 用户手动填的评分不会被刷新冲掉；
- 新建 `elective` 自动 `participating: true`，新建 `builtin` 自动 `selected: true`。

> 因此**不需要**新增导入端点；插件把数据规整成 `add_course` 命令即可，命令通道与 AI/外部工具完全统一。

### 7.2 「候选 / 已选 / 内置」三类按钮语义 `[决定]`

| 教务页面 | 按钮文案 | 目标 `category` | 效果 |
|---|---|---|---|
| 课程信息 / 开课情况 | 「加入候选」 | `elective`（可配置为 `required`） | 进候选池，`selected: false`，参与排课枚举 |
| 课程信息 / 开课情况 | 「加入必修候选」 | `required` | 多候选必选其一 |
| 我的已选课 | 「导入为已选课」 | `builtin` | 单候选 `selected: true`，等同内置课 |

- 重复点击同一门课 → 仅刷新 `segments`/`enrolled`/`capacity`，不重复建课、不改动 `category`（如需改类别用 `update_course`，列为可选增强）。

### 7.3 联动闭环

1. 教务页点按钮 → content script 解析/查询 → 消息给 background。
2. background POST `/api/command` → 服务端落盘当前存档。
3. 已打开的选课助手标签页 **2 秒内自动刷新**（现有轮询机制，无需改前端）；未打开则经 popup 深链打开全屏页。

## 8. 关键设计决定汇总 `[决定]`

1. **形态 = 插件 + 服务器共存，插件保持薄**（§3）；不把整个应用搬进插件。
2. **Manifest V3 + Chromium**（Chrome/Edge 同源，Firefox 另作兼容，见 §12）。
3. **localhost 流量走 background**（规避 CORS 与混合内容）；**教务系统请求走 content script**（同源，自动带会话）。
4. **复用 `shared/webtext.ts` 解析器**：插件 DOM 层只做「DOM → 规范化文本」重建，不重写解析规则；静默请求结果同样规整为 `ParsedCourse`。
5. **复用 `/api/command`**：不新增导入端点，与 AI/外部工具共享同一命令通道与去重/合并语义。
6. **权限最小化**：不申请 `cookies`/`webRequest`，不读、不存、不转发任何密码或 Cookie。
7. **主界面保持全屏标签页**（§9），插件只做「抓取 + 快捷按钮 + 深链打开」，不内嵌课表 UI。

---

## 9. 「铺满标签页」约束

- 主应用已使用 `min-height: 100vh` + 全宽 flex 布局（见 `src/App.css` / `index.html` viewport meta），**天然铺满标签页**；本约束在集成中保持不变。
- 插件**不在 popup/side panel 里塞课表**：popup 仅状态 + 深链；真正的操作始终在 `http://localhost:3001` 的全屏标签页进行，保证课表网格、候选面板、结果区的操作效率与现有体验一致。
- 若后续要「教务页侧边栏快速预览」，可作为**扩展项**另做（`sidePanel` API），不改变主操作页铺满标签页的前提。

## 10. 权限与安全

| 项 | 说明 |
|---|---|
| 账号密码 | 插件**永不接触**；登录完全由用户在浏览器内完成 |
| Cookie/token | 不读、不存、不转发到任何第三方；仅在用户自己的教务页内发起同源请求 |
| 数据去向 | 唯一外发目标是 `http://localhost:3001`（用户本机）；无任何远程服务器 |
| 明文密钥 | 与本应用现有约定一致，DeepSeek key 仍仅存本机 `data/settings.json`，与插件无关 |
| 代码来源 | 插件为本项目自建、本地加载（开发者模式）或私有分发，不上架公共商店 |

## 13. 附录 A：教务系统实测结构（已确认，来自网页文件）

> 依据：`首页.html` / `全校开课查询.html` / `选课.html`（及各自 `_files`）。域名 `https://jwxt.nwpu.edu.cn`。

### 13.1 页面与技术栈

| 页面 | 入口 URL | 技术栈 | 认证 |
|---|---|---|---|
| 全校开课查询 | `/student/for-std/lesson-search/index/308509` | 服务端渲染 + jQuery/DataTables（semi-auto-table） | 会话 Cookie |
| 选/退课 | `/student/for-std/course-select` → 跳转 `/course-selection/` | Vue CLI SPA + axios | `Authorization` token（`withCredentials:false`） |

### 13.2 开课查询：静默请求端点（已确认）

```
GET /student/for-std/lesson-search/semester/{semesterId}/search/308509
    ?courseCodeLike=D01M11011
    &assembleFields=course.code,minorCourse.nameZh,courseType,openDepartment,teacherAssignmentList,examMode,campus,teachLang,roomType,timeTableLayout,crossBizTypes,courseProperty
```

- 表单字段即查询参数：`courseCodeLike`(课程代码)、`courseNameZhLike`(课程名称)、`teacherAssoc`(教师)、`weekIndexs`(星期)、`courseIndexs`(节次)、`stdCountGte/Lte`(已选范围)、`limitCountGte/Lte`(容量范围)、`campusAssoc`(校区)、`compulsory`(是否必修) 等。
- **响应为 DataTables 结构化 JSON**，每行（一个教学班 = 一个候选）关键字段：

| 响应字段 | 含义 | 映射 |
|---|---|---|
| `course.code` / `course.nameZh` / `course.credits` | 课程编号 / 名称 / 学分 | `code` / `name` / `credit` |
| `code` / `nameZh` | 教学班编号 / 名（如 `D01M11011.01`） | `option.label` |
| `stdCount` / `limitCount` | 实际已选 / 上限 | `enrolled` / `capacity` |
| `teacherAssignmentList[].person.nameZh`(+`role`) | 授课教师 | `segment.teacher` |
| `scheduleText.dateTimePlacePersonText.textZh` | 时间地点文本（`3~6周 周六 第一节~第四节 友谊校区 诚字楼212 薛小锋`） | 解析为 `segments` |
| `suggestScheduleWeeksInfo` | 建议排课周次（`3~6`） | 周次参考 |

- **「一次性查某课全部开课时间+教师」** = 带 `courseCodeLike=<编号>` 调一次，返回该课所有教学班（候选），每班一条，含全部时间段 + 教师 + 已选/容量。**静默请求 100% 可行，且为结构化 JSON，最稳。**

### 13.3 开课查询：DOM 抓取结构（已确认，兜底）

- 结果表格 8 列：`[0] 复选框(model_id=教学班id) [1] 课程信息 [2] 教学班 [3] 学分 [4] 教师 [5] 期中退课 [6] 周次 [7] 时间地点`。
- 每个单元格几乎都带 `data-text` 干净全文本（如 `.course-name[data-text]`、`.lesson-code[data-text]`、`.course-datetime-place[data-text]`），DOM 抓取只需读 `data-text`，**比粘贴文本更可靠**。
- 课程信息列内嵌 `实际/上限人数`（`stdCount/limitCount`）→ 直接给 `enrolled/capacity`。
- 与既有 `docs/西工大课程网页文本格式.md` 的 7 列规则完全吻合（教学班 / 学分 / 教师 / 期中退课 / 周次 / 时间地点 + 课程信息）。
