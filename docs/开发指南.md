# 选课助手 · 开发指南（面向 AI / 新开发者）

> 本文是**代码地图 + 扩展手册**：读完可完整理解项目结构、数据流与约定，无需逐个文件翻源码即可上手写功能。
> 使用/功能说明见根目录 `开发说明.md`；原始设计稿见 `DESIGN.md`（部分术语已演进，以本文为准）；外部 AI 调用接口见 `docs/AI接口协议.md`。

---

## 1. 一句话概览

本地运行的「大学生选课 / 排课」网页应用 + 浏览器插件：

- 网页端（React + Vite）在浏览器里编辑课程、生成「时间不冲突 + 学分不超限」的可行课表组合；
- 本地后端（Node + Express）负责存档读写、结构化命令入口、规则解析；
- 浏览器插件（Chrome/Edge MV3）从教务系统抓取课程与已选人数/容量，写入同一份存档；
- 数据存在 `data/saves/<id>.json`（JSON 文件，前端 2 秒轮询自动同步外部改动）。

技术栈：`React 18 + TypeScript + Vite 5`（前端）、`Express 4`（后端）、`esbuild`/`@yao-pkg/pkg`（打包）、`tsx`（跑 TS）。

## 2. 运行与脚本

| 命令 | 作用 |
|---|---|
| `npm install` | 装依赖 |
| `npm run dev` | 前端 5173（Vite）+ 后端 3001（tsx watch）并行，热更新 |
| `npm run build` | `tsc --noEmit && vite build` → `dist/` |
| `npm start` | 仅起后端（tsx server/index.ts），托管 `dist/` + API |
| `npm run test:ext` | 插件核心逻辑单测（`tsx --test extension/test/*.test.ts`） |
| `npm run build:ext` | 打包插件 → `extension/dist/` |
| `npm run pack:win` / `pack:linux` | 打可执行文件 → `releases/<平台>-<架构>-<版本>/` + zip |
| `npm run pack:src` | 打「源码版」zip（供有 Node 的人自建） |
| `npm run build:tray` | 打 Windows 托盘壳（需 Rust，见 `tray/README.md`） |

端口约定：后端默认 `3001`，**被占用时自动向后顺延并持久化**（写进 `data/settings.json` 的 `port`）；插件 `host_permissions` 已是 `http://localhost/*`（任意端口），插件弹窗会自动同步当前页端口。

## 3. 架构与数据流

```
浏览器（React）
  ├─ Zustand? 否——用 useState + 自定义 hooks
  ├─ 状态变更 → shared/mutations 纯函数 → 新 Schedule → debounce PUT /api/schedule
  └─ 每 2 秒 GET /api/schedule 轮询（外部改档后自动刷新）
        │
        ▼  HTTP /api/*
后端（Express，server/index.ts）
  ├─ 存档读写（data/saves/<id>.json，原子写 + 手动备份 /api/saves/:id/backups）
  ├─ POST /api/command  → shared/commands.applyCommand（结构化命令）
  ├─ POST /api/parse    → shared/parser.parseCommands（规则解析）
  └─ 静态托管 dist/
        │  读写
data/saves/<id>.json + data/settings.json + data/backup/

浏览器插件（extension/，独立进程）
  └─ 教务页抓取 → 命令 → POST http://localhost:<port>/api/command → 同一存档
```

**关键原则**：所有数据修改（网页 UI、AI、插件）最终都走**结构化命令（Command）**或**直接改 JSON 文件**，落到同一份存档；后端 `applyCommand` 是唯一「命令 → Schedule」的执行点。

## 5. 数据模型（`shared/types.ts`）

```ts
type Category = 'builtin' | 'required' | 'elective';

interface Segment {   // 最小时间段单元（对齐 WakeUp 打散模型）
  day: number;        // 1=周一 … 7=周日
  startNode: number;  // 起始节
  step: number;       // 连节数（区间 [startNode, startNode+step)）
  startWeek: number;  // 起周（闭区间）
  endWeek: number;    // 止周
  room: string;       // 段级字段（不同周可不同地点）
  teacher: string;    // 段级字段（不同周可不同老师）
}

interface Option {    // 候选方案（一个教学班）
  id: string; label: string;
  rating: number;             // 候选总体评分 0~5
  selected: boolean;          // 「确认选」（确认要选，≠选课成功）
  enrolled: number;           // 已选人数 m
  capacity: number;           // 容量 n
  selectable?: boolean;       // 是否开放选课
  locked?: boolean;           // 锁定：粘贴/解析不覆盖
  segments: Segment[];
}

interface Course {
  id: string; code: string; name: string;
  category: Category; credit: number;
  willingOverride: number | null;   // 手动覆盖意愿值
  participating?: boolean;          // 是否参与排课（必修/非必修均可关）
  linkId?: string;                  // 串联组：同组只选其一
  color: string;
  options: Option[];
}

interface Meta {
  school; term; startDate; daysPerWeek; nodesPerDay; totalWeeks;
  creditCap; willingBudget;
  weekComboColors?; dividerNodes?; rowHeight?; evenCardWidth?; focusDimOpacity?;
}

interface Schedule { meta: Meta; nodeTimes: NodeTime[]; teacherRatings: TeacherRating[]; courses: Course[]; }
interface Settings { currentSaveId?: string; port?: number; }
```

### 术语（务必理解，易踩坑）

| 术语 | 含义 | 意愿值 |
|---|---|---|
| **内置课 builtin** | 已选课成功、固定不可改 | **不计** |
| **必修课 required** | 多候选，必选其一 | 计 |
| **非必修 elective** | 可选 0~K 门（`participating` 才参与） | 计 |
| **确认选 selected** | 确认要选该候选（**≠选课成功**），同级候选退出枚举 | 计 |
| **串联组 linkId** | 同组课程排课时只选其一 | — |

- 编号 `code` 是查重主键（无编号则按 `name`）。
- `rating`/`enrolled`/`capacity` 在**候选级**；`teacher`/`room` 在**段级**。

## 6. 核心算法（`src/lib/algo.ts` + `schedule.ts` + `colors.ts`）

### 6.1 冲突检测（algo.ts）

```ts
segmentsConflict(a, b)  // 同 day 且节次重叠 且 周次重叠
optionsConflict(a, b)   // 存在任一对 Segment 冲突
combinationConflicts(opts)  // 两两判断
```

### 6.2 意愿值（algo.ts）

```ts
willingValue(m, n) { if (m <= n) return 0; v = round(sqrt(m-n) * exp(m/n)); if (v%5===0) v+=1; return v; }
effectiveWilling(course, option)  // willingOverride ?? willingValue(enrolled, capacity)
```

总意愿值 = 必修 + 非必修（**确认选 + 待选**）求和，**仅内置课不计**。

### 6.3 组合枚举与排序（algo.ts `enumerateSchedules`）

1. 固定课程 = `fixedItems(schedule)`（内置 + 已确认选，来自 schedule.ts）。
2. 必修笛卡尔积 × 非必修子集（大小 ≤ K）→ 过滤冲突与学分超限。
3. 排序：`final_score = 0.3*rating_score + 0.7*willing_score`（意愿越少越好）。

`diagnoseNoSolution` 给出无解原因（学分超限 / 固定课冲突 / 必修被堵死 / 必修两两无法同时安排）。

### 6.4 布局与配色（schedule.ts / colors.ts）

- `dayBlocks`：把时段合并成「块」；`layoutBlocks`：重叠块按 lane 并排。
- `resolveCourseColors`：黄金角分色（同表内课程颜色尽量不同）；`comboColor`：候选按星期组合着色；`tintColor`：半透明底。

## 7. 命令系统（`shared/commands.ts` + `shared/mutations.ts`）

### 命令类型（Command）

`add_course` / `add_option` / `update_option` / `set_selected` / `set_rating` / `set_enrollment` / `set_willing` / `update_course` / `delete_course` / `update_meta`。

### 执行入口

```ts
applyCommand(schedule, cmd): Schedule   // 单条
applyCommands(schedule, cmds): Schedule // 批量（顺序应用）
```

- `add_course` 会按 `code`（无则 `name`）查重合并候选；候选按 `label`（教学班编号）去重；`locked` 候选不被覆盖。
- **所有 UI/AI/插件的修改最终都落在这里**，是扩展数据能力的统一入口。

### mutations.ts（不可变纯函数）

`addCourse/updateCourse/deleteCourse/setCategory/addOption/updateOption/removeOption/setSelected/toggleSelected/addSegment/updateSegment/removeSegment/emptyOption/emptySegment`。前端 `update((s) => someMutation(s, ...))` 后由 `useSchedule` 落盘。

## 8. 规则解析器（`shared/parser.ts` + `webtext.ts`）

```ts
interface ParseRule { name: string; parse(text, schedule): Command[] | null }
export const parseRules: ParseRule[]  // 按顺序尝试，命中即返回
export function parseCommands(schedule, message): Command[]
```

现有规则：教务网页文本（`parseWebCoursesText`）、添加课程、删除课程、改类别、已选/容量、评分。

**加一条解析规则**：在 `parseRules` 里插入一个 `{ name, parse }` 对象即可，`parse` 返回 `Command[]` 或 `null`。

## 9. 前端结构与约定

- **根组件 App.tsx 只做编排 + 渲染**；副作用与状态都在 `src/hooks/` 的 hook 里。
- **组件是「props 进、回调出」的展示型组件**；共享 UI 用 `Modal`/`Field`；共享常量用 `lib/labels.ts`；数字解析用 `lib/num.ts`。
- **共享逻辑放 `shared/`（前后端/插件都能用）或 `src/lib/`（插件会 `import '../../src/lib/...'` 复用）**。
- 关键 hook：
  - `useSchedule`：返回 `{ schedule, error, saving, update, setAndSave, replace }`。`update(fn)` 是最常用的修改方式；`replace(s)` 用于外部（AI/解析/切换存档）整体替换且不重复落盘。
  - 其余 hook 见 §4 文件职责。

### 数据流示例：给课程加学分字段

1. `shared/types.ts` 的 `Course` 加字段；
2. `shared/mutations.ts` 已有 `updateCourse`（通用 patch，无需改）；如需专门命令 → `shared/commands.ts` 加 `case`；
3. UI 在 `CoursePanel.tsx` 里用 `<Field>` + `update((s) => updateCourse(s, id, { xxx }))`。

## 10. 浏览器插件（extension/）

### 架构

- **background.ts**：service worker，统一 `fetch(baseUrl/api/...)` 转发（规避 CORS），消息协议见 `messaging.ts`（`ExtMessage`/`ExtResponse`）。
- **content.ts**：在教务页注入按钮，收集勾选行 / 静默查询 / 预览，通过 `chrome.runtime.sendMessage` 交给 background。
- **数据流**：`DOM/JSON → RawLesson → ImportedCourse → add_course 命令 → /api/command`。
- **updateEnrollment.ts**：按 `course.code == lesson.courseCode`、`option.label == lesson.lessonCode` 匹配，生成 `set_enrollment` + `update_option(selectable)` 命令。
- **popup.ts**：点图标时，若当前页是选课助手（localhost + 标题含「选课助手」）→ 自动把 `baseUrl` 同步为该端口。

### 加一个「新抓取来源」

1. 写一个 `xxxExtractor.ts` 把来源数据规整成 `RawLesson[]`（见 `model.ts` 的 `RawLesson`）；
2. 在 `index.ts` barrel 导出；
3. 在 `content.ts`/`background.ts` 接对应消息类型。

## 12. 约定与易踩坑

1. **「确认选」≠「选课成功」**：`option.selected` 是「确认要选」；只有 `category === 'builtin'` 才是「已选课成功」。
2. **意愿值只对「必修+非必修」计**，内置课不计；超容量（`enrolled > capacity`）才非 0。
3. **端口自动切换**：后端 3001 被占会顺延并把成功端口写进 `settings.json.port`；插件 `host_permissions` 已放开任意端口，弹窗会自动同步。
4. **数据目录**：后端用 `IS_PKG ? dirname(process.execPath) : process.cwd()` 作为 `BASE`，`data/` 和 `dist/` 都在 `BASE` 下。
5. **pkg 打包必须加 `--public --public-packages '*'`**（否则跨平台字节码报 `V8 rejected the bytecode cache`）。
6. **测试集中**在 `extension/test/`，新增测试放这里，命名为 `*.test.ts`。
7. **共享代码单一来源**：`segmentsEqual` 在 `shared/segment.ts`；UI 常量在 `src/lib/labels.ts`；`num` 在 `src/lib/num.ts`；别在各处重复定义。
